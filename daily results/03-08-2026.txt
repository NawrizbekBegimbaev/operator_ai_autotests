2. STAGING-ONLY FIXTURE API С АВТООЧИСТКОЙ
-------------------------------------------

Главный блокер сняли не «походом в базу руками», а отдельным набором
служебных маршрутов, которые существуют только на staging:

- создание временного Оператора с префиксом `AT-*`, назначения воронки,
  лидов, попыток дозвона, AI- и PBX-сессий;
- разрешённые автоматические переходы статусов без ожидания реального
  фонового интервала;
- маршруты принимают только ROP той же компании и только временные `AT-*`
  учётные записи;
- в production этих маршрутов нет.

Каждый сценарий в блоке `finally` удаляет за собой всё: лидов, сессии,
PBX-события, назначение воронки и временного Оператора. Синтетические лиды
никогда не отправляются во внешнюю AmoCRM.

Отдельно решена рабочая проблема: UAT-оператор не мог получить полную
тестовую воронку из-за лимита в двух операторов. Добавлено staging-only
назначение только для временных учёток, которое всегда удаляется после
сценария.

4. НАЙДЕННЫЕ И ЗАКРЫТЫЕ ДЕФЕКТЫ
--------------------------------

BUG-047 (P1). Готовый AI-результат не открывался при восстановлении
wrap-up сессии, если WebRTC уже зарегистрирован.

Причина: опрос сессии полностью отключался при зарегистрированном WebRTC,
включая уже завершённую сессию `wrap_up`. Интерфейс оставался на экране
звонка, а готовая AI-рекомендация не показывалась.

Исправление: опрос пропускается только для активного звонка в браузере;
восстановленная `wrap_up` сессия продолжает опрашиваться. Ретест UAT-OP-007
на staging прошёл, включая видимый AI-summary и одно автосохранение через
20 секунд.

BUG-048 (P2). Общая причина «первый звонок» скрывала статусную причину
«Bugun keladi».

Причина: признак «первый звонок» проверялся раньше класса статуса и
подменял статусную причину общим текстом.

Исправление: статусные причины получили приоритет; текст первого звонка
используется только для статуса без собственной бизнес-причины. Ретест
UAT-FLOW-002 прошёл.

Оба дефекта записаны в русский и узбекский журналы со steps to reproduce.

12. ПОДСКАЗКИ (HINT) ДЛЯ СТАТУСОВ
----------------------------------

На экране правил ROP у пяти статусов стояло «Hint hali yozilmagan» —
подсказка не заполнена. По коду выяснилось, почему это важно:

- текст подсказки уходит прямо в запрос к AI, и AI выбирает статус только
  тогда, когда исход разговора явно совпадает с подсказкой;
- этот же текст показывается оператору как описание статуса в окне
  подтверждения результата звонка.

То есть пустая подсказка означает, что у AI нет основания выбрать статус,
а оператор не видит пояснения.

Подготовлены тексты на узбекском для пяти статусов: ko'tarmadi,
chala gaplashdi, keyingi qo'ng'iroq vaqti, Uchrashuv vaqti, bugun keladi.

Каждая подсказка построена одинаково: когда выбирать этот статус и чем он
отличается от соседнего. Соседние пары — ko'tarmadi / chala gaplashdi,
chala gaplashdi / keyingi qo'ng'iroq vaqti, Uchrashuv vaqti / bugun keladi —
это самые вероятные места ошибки AI.

В подсказки вынесены два реальных правила системы, о которых легко забыть:

- у статуса «keyingi qo'ng'iroq vaqti» обязательно заполнять время: без него
  лид навсегда выпадает из очереди обзвона;
- у статуса «bugun keladi» лид выдаётся за 60 минут до визита, а если время
  визита не указано — с начала рабочего дня.

Тексты переданы тестировщику, вставка выполняется вручную через экран правил.
