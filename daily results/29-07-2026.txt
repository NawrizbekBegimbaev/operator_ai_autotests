ОТЧЁТ ЗА 29.07.2026
====================

КРАТКИЙ ИТОГ
-------------

29 июля мы продолжили системную проверку staging Operator AI: настроили
локальный запуск автотестов, выполнили пакет проверок авторизации, прав доступа,
управления операторами и звонков, а затем вручную перепроверили найденные
отклонения в Safari.

Главный результат:

- контрольный автоматический пакет завершён с итогом 12 пройденных проверок
  и 4 ожидаемых xfail по уже известным проблемам;

- подтверждены шесть новых реальных дефектов: BUG-022, BUG-023,

  backend и Safari;

  журналов;
- русская и узбекская версии журнала синхронизированы;
- временные пользователи удалены, пароли и активность исходных учётных записей
  восстановлены;
- production не использовался, все функциональные действия выполнялись только
  на staging.

3. ПРОВЕРИЛИ ОГРАНИЧЕНИЕ ПОПЫТОК ВХОДА — TC-011
-------------------------------------------------

Проверку выполнили отдельной последовательностью на staging с несуществующим
логином, чтобы не блокировать основные тестовые учётные записи.

Результат:

- попытки 1–5 вернули HTTP 401;
- текст для неверных данных был `login yoki parol noto'g'ri`;
- шестая попытка вернула HTTP 429;
- `detail` содержал технический текст `rate limit exceeded`;
- тело содержало `retry_after_seconds=12`;
- HTTP-заголовок `Retry-After` отсутствовал;
- JSON-тело было возвращено с `Content-Type: text/plain`.

Ограничение частоты запросов работает, но пользовательское сообщение,
заголовки и тип ответа оформлены неправильно.

Создан BUG-022:
«После превышения лимита входа показывается техническое сообщение
rate limit exceeded».

9. ПРОВЕРИЛИ КАРТОЧКУ ОПЕРАТОРА — TC-060
-----------------------------------------

Для Оператора `Soska` через API подтверждено:

- назначена одна воронка;
- присутствуют записи звонков;
- API возвращает `pipeline_name`.

Карточка правильно показала:

- имя и username;
- телефон;
- внутренний номер;
- статус Онлайн/Оффлайн;
- рабочие часы;
- записи звонков;
- кнопку возврата.

При этом метка «Воронка: …» отсутствовала.

Проверка кода показала рассинхрон формата:

- backend возвращает `{ items: [...] }`;
- frontend ожидает обычный массив и читает `data[0]`.

Создан BUG-024:
«Карточка Оператора не показывает назначенную воронку».

Дефект дополнительно подтверждён вручную в Safari.


10. ПРОВЕРИЛИ ПОТЕРЮ СЕТИ — TC-091
-----------------------------------

Автоматический вариант:

- до ошибки отображались четыре сделки;
- запрос `/v1/amocrm/deals` был сделан недоступным;
- страница сохранила оболочку, но показала техническое `Network Error`;
- после восстановления соединения вернулись все четыре строки без дублей.

Ручной вариант в Safari:

- Оператор открыл «Рабочий стол»;
- Wi‑Fi был полностью отключён;
- выполнен переход в «Звонки»;
- lazy-модуль маршрута не загрузился;
- приложение полностью заменило интерфейс экраном
  `Unexpected Application Error!`;
- пользователю показан внутренний текст
  `Failed to fetch dynamically imported module`;
- раскрыт внутренний URL файла из `/assets/`.

Создан BUG-025 и после ручной проверки повышен до P2:
«При потере сети раздел “Звонки” падает с технической ошибкой загрузки
модуля».


11. ВРУЧНУЮ ПРОВЕРИЛИ ЗАПИСИ И ДЕТАЛИ ЗВОНКОВ
----------------------------------------------

В карточке Оператора записи звонков отображались с:

- номером;
- направлением;
- длительностью;
- waveform;
- синей кнопкой Play.

При нажатии Play:

- звук не начинался;
- кнопка не переходила в Pause;
- индикатор оставался `0:00 / 0:00`.

Создан BUG-026:
«В карточке Оператора не воспроизводятся записи звонков».

При нажатии на строку звонка открывалась страница «Транскрипт звонка», но:

- поля «Событие», «Направление», «Звонящий», «Принимающий»,
  «Длительность» и «Время» содержали `-`;
- показано «Не удалось загрузить данные звонка»;
- аудиоплеер показывал `0:00`;
- транскрипт отсутствовал.

Создан BUG-027:
«Страница выбранного звонка открывается без данных».

BUG-026 и BUG-027 оформлены отдельно, потому что это разные пользовательские
действия и разные точки отказа, даже если техническая причина окажется общей.
