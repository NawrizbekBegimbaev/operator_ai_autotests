# Отчёт за 28–29.07.2026

Этот файл объединяет результаты двух параллельных QA-сессий. Работы второй
сессии описаны в основной части, независимые работы первой сессии — в
отдельном дополнении ниже.

## Кратко

- Всего в репозитории автоматизированы 27 тест-кейсов: 24 первой сессией и
  TC-027, TC-028, TC-029 второй сессией.
- Ещё 6 кейсов зарегистрированы как `manual_setup`, чтобы они не терялись из
  отчётности.
- Все 400 кейсов библиотеки разделены на 156 кандидатов для автоматизации и
  244 ручные проверки или проверки, зависящие от подготовки стенда.
- Последний контрольный прогон авторизации первой сессии:
  `5 passed in 31.37s`.
- Проверены 11 запрещённых прямых переходов для РОП и Super-admin.
- Три новых дефекта подтверждены как настоящие: BUG-019, BUG-020 и BUG-021.
- Один неподтверждённый кандидат BUG-022 удалён из журнала.
- Для ручной проверки самого серьёзного дефекта подготовлен набор из семи
  запросов Bruno с автоматическим созданием и удалением временного оператора.
- Секреты, пароли, токены и адреса окружений в Git не добавлялись.

## Что сделано 28.07.2026

### 1. Автоматизировали TC-027, TC-028 и TC-029

Проверили, что пользователь не может открыть по прямой ссылке страницы,
предназначенные для другой роли:

- РОП не должен открывать рабочие страницы оператора;
- Super-admin не должен открывать настройки РОП;
- Super-admin не должен открывать рабочие страницы оператора.

Для каждого адреса проверялось не только содержимое экрана, но и отсутствие
кратковременной утечки данных. Даже если страница успела бы появиться на долю
секунды, проверка должна была это заметить.

Отдельно проверили страницу начала звонка. При запрещённом переходе система:

- не запросила очередь звонков;
- не запросила следующего лида;
- не захватила лида за пользователем неправильной роли.

Результат staging-прогона:

- проверено 11 запрещённых адресов;
- `11 xfailed in 95.59s`;
- все проверки отсутствия защищённых данных прошли;
- ожидаемая страница `Permission denied` не появилась;
- вместо неё система перенаправляла пользователя на стартовую страницу его
  роли.

Здесь `xfail` означает не пропуск проверки, а известный дефект: тест полностью
выполняется и фиксирует неправильное поведение, пока разработчики его не
исправят.

### 2. Исследовали проблему прямых запрещённых ссылок

Подтвердили важное различие:

- РОП и Super-admin не получили содержимое чужих страниц;
- защищённые ответы API не были получены;
- проблема заключается в неправильной реакции интерфейса: редирект вместо
  понятной страницы «нет доступа».

Дефект сохранён в журнале как BUG-020.

### 3. Проверили право Super-admin изменять операторов РОП

Автоматическая API-проверка создала временного оператора под тестовым РОП,
после чего Super-admin попытался изменить его имя.

По требованиям Super-admin должен иметь доступ только для просмотра. Сервер
должен вернуть отказ HTTP 403 и оставить запись без изменений.

Фактически сервер вернул HTTP 200 и сохранил новое имя. Это нарушение
серверного разграничения прав. Дефект сохранён как BUG-021 с приоритетом P1.
После проверки временный оператор удаляется под тем РОП, которому он
принадлежит.

### 4. Навели порядок в журнале дефектов

Первоначально переход оператора на «Рабочий стол» после входа был записан как
отдельный баг. После уточнения владелец продукта подтвердил, что это правильное
поведение, а старое ожидание тест-кейса было устаревшим.

Карточку со статусом «Не баг» удалили из русского и узбекского журналов.
Последующие настоящие дефекты перенумеровали, а все ссылки в автотестах
синхронно обновили:

- прежний BUG-020 стал BUG-019;
- прежний BUG-021 стал BUG-020;
- прежний BUG-022 стал BUG-021.

После изменения обе версии журнала содержали непрерывную нумерацию
BUG-001…BUG-021. Дополнительно собрали затронутые тесты:
`8 tests collected in 0.04s`.

## Что сделано 29.07.2026

### 1. Вручную разобрали новые баги по одному

Вместе с QA повторно проверили каждый новый дефект и отдельно уточнили, является
ли наблюдаемое поведение ошибкой продукта.

Итог:

- **BUG-019 подтверждён:** форма входа принимает пароль из шести или семи
  символов, но сервер требует минимум восемь и показывает техническое
  `validation failed`. Клиент и сервер используют разные правила.
- **BUG-020 подтверждён:** при прямом переходе в запрещённый раздел
  пользователь видит редирект вместо предусмотренной страницы
  `Permission denied`.
- **BUG-021 подтверждён:** Super-admin может через API изменить оператора,
  принадлежащего РОП, хотя ему разрешён только просмотр.

Таким образом, все три актуальных новых дефекта признаны настоящими и остаются
в журнале.

### 2. Подготовили ручную проверку BUG-021 в Bruno

Создали отдельную коллекцию Bruno из семи последовательных запросов:

1. вход под тестовым РОП;
2. создание временного оператора;
3. вход под Super-admin;
4. чтение оператора до изменения;
5. попытка изменения оператором с неправильными правами;
6. повторное чтение и сравнение данных;
7. обязательное удаление временного оператора.

Коллекция сама создаёт уникальные тестовые данные, передаёт между запросами
токены и ID только в памяти Bruno и очищает временную запись в конце.

Проверка качества коллекции:

- разобраны все 7 файлов запросов;
- успешно проверены 20 JavaScript-блоков;
- реальные пароли и токены в файлы не записаны;
- адрес API хранится только в локальном `.env`, исключённом из Git.

Во время первого ручного запуска обнаружили несовместимость со встроенной
QuickJS-средой Bruno: объект `URL` был недоступен. Скрипт переписали на
совместимый вариант и повторно проверили.

### 3. Разобрали кандидат BUG-022

Параллельная сессия добавила карточку о том, что staging якобы иногда отдаёт
HTML вместо JavaScript и CSS, из-за чего интерфейс остаётся пустым.

Провели ручную проверку в Яндекс Браузере с открытыми инструментами
разработчика и отключённым кешем:

- страница входа загружалась;
- форма появлялась нормально;
- длительной белой страницы не было;
- короткий белый экран на долю секунды оказался обычным этапом загрузки
  браузера, незаметным пользователю.

Кандидат не воспроизвёлся. По решению QA BUG-022 полностью удалён из русского
и узбекского журналов. Поскольку он был последним, перенумерация остальных
дефектов не потребовалась. Текущий журнал заканчивается на BUG-021.

## Дополнение первой параллельной сессии

### 1. Автоматизировали вход и управление сессией

TC-011 не имитирует успешную проверку. Он зарегистрирован тестом с маркерами

### 2. Настроили базовую архитектуру быстрых независимых тестов

В общей конфигурации автотестов реализованы:

- ленивый сессионный кэш API-токена отдельно для каждой роли;
- блокировка кэша для безопасного параллельного запуска;
- сессионный кэш Playwright `storage_state` отдельно для Super-admin, РОП и
  оператора;
- новый независимый контекст браузера для каждого теста из сохранённого
  состояния роли;
- фиксированный viewport 1920×1080;
- Page Object Model: локаторы и действия находятся в page-объектах, проверки —
  только в тестах;
- семантические локаторы и автоматические ожидания Playwright без `sleep`;
- уникальные тестовые данные и очистка через API там, где тест создаёт записи.

Таким образом, обычные RBAC/UI-тесты не выполняют повторный вход на каждом
кейсе, но остаются независимыми друг от друга.

### 3. Автоматизировали проверки ролей и изоляции

Первая сессия покрыла TC-021…TC-026, TC-030…TC-033 и TC-040…TC-042:
