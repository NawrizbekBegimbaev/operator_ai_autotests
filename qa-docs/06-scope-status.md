## 1. Легенда диаграмм

| Цвет | Значение | Действие QA |
| --- | --- | --- |
| 🔴 Красный | Старое правило отменено | Проверить, что старый механизм действительно удалён |
| 🔵 Синий | Новое правило заявлено как реализованное | Сверить по коду и проверить на staging |
| 🟣 Фиолетовый | Решение утверждено, но ещё не реализовано | Подготовить кейсы, держать их вне общей статистики до релиза |
| Без цвета | Старое правило не менялось | Проверять как часть основного потока |

Синий цвет не заменяет техническую проверку. Если синий элемент отсутствует в коде, это расхождение, а не «готово по умолчанию».

| ID | Требование | Что осталось в коде | Риск | Покрытие |

| **DGM-02** | E4: недозвон увеличивает только попытку; статус AmoCRM не меняется автоматически | Админка предвыбирает `Ko'tarmadi`; 20-секундный таймер может отправить его без действия оператора | Искажение воронки AmoCRM | **TC-352** |

| **DGM-04** | E7: смена автоматически закрывается после N минут без звонков | Планировщик закрывает только смены прошлых дней в 23:59:59 | Неверный учёт рабочего времени | **TC-356**, отложен; N не определено |

## 5. Детали, важные для приёмки

### 5.1 Жизненный цикл

- Четыре попытки — **общий лимит**, а не четыре попытки в день.
- Неиспользованный остаток переносится на следующие рабочие дни.
- Недозвон сам по себе не является разрешением записать `Ko'tarmadi`.
- `Sifatsiz` ставится системным правилом после 4/4 или человеком, но не AI.
- `Yangi` и `Sifatsiz` не должны появляться в выпадающем списке исходов.
- Общая ветка «не заполнены обязательные поля → Chala» сохраняется.
- Для поля Operator действует исключение E6: система подставляет вошедшего оператора и не пытается угадать его имя по аудио.

### 5.2 Очередь

- Постоянной связи «этот лид принадлежит этому оператору» нет.
- Связь оператора с воронками определяет доступный пул, но не владение конкретным лидом.
- Захват должен быть атомарным: два оператора не получают одного лида.
- `Bugun keladi` выдаётся за час до времени визита.
- Время перехода дня встречи настраивается ROP, по умолчанию 00:00.

### 5.3 AmoCRM

- Operator AI не должен заставлять ROP вручную строить статусы и форму, если они уже существуют в AmoCRM.
- Синхронизация должна учитывать несколько воронок одного ROP.
- Для каждой воронки нужен собственный набор статусов и полей группы `Operator AI`.
- Двунаправленные вебхуки и ограничение частоты запросов остаются частью основной интеграции.
- Значение `AMOCRM_WEBHOOK_URL` хранится только в окружении; секретные URL и токены в документацию не копируются.

### 5.4 Смена

Текущий код продолжает закрывать незавершённую смену прошлой даты временем 23:59:59. Целевое автозакрытие по E7 ещё не определяет:

1. значение N;
2. что считать активностью;
3. взаимодействие с ручным перерывом;
4. возможность начать новую смену в тот же день.

До ответа TC-356 остаётся заблокированным.

## 6. Приоритет проверки на staging

1. **P0:** TC-351 — система не звонит на номер OnlinePBX как на второй номер клиента.
2. **P0:** TC-352 — недозвон не меняет статус AmoCRM автоматически.
3. **P0:** TC-354 — разные воронки не смешивают поля формы.
4. **P1:** полный цикл четвёртой попытки → `Sifatsiz` → AmoCRM → выход из очереди.
5. **P1:** два оператора одновременно забирают разных лидов.
6. **P1:** TC-353 — Operator подставляется по вошедшему пользователю и не меняется из-за имени в аудио.
7. **P1:** ретрай за пределами рабочего дня переносится на следующее рабочее утро.
8. **P2:** двуязычие интерфейса при узбекских названиях статусов.

Все функциональные проверки выполняются только на staging/test. Production разрешён только для пассивного наблюдения без изменения данных.

## 7. Критерий актуальности этого файла

Карту нужно обновить, если произошло хотя бы одно событие:

- изменилась одна из двух диаграмм;
- обновился `project/back` или `project/admin`;
- реализована фиолетовая функция;
- на staging воспроизведён DGM-01, DGM-02 или DGM-05;
- команда определила N и правила автозакрытия по бездействию.

При обновлении сначала фиксируется новый commit SHA, затем повторяется сверка кода и только после этого меняются статусы и Excel.
